Встроены в тот же скрипт alert_webhook.py.

Структура блока:

    - 'IP1:ПОРТ'
    - 'IP2:ПОРТ'
  labels:
    cluster: 'имя ИС'
    role: 'postgres'
    env: 'production'

5. ДОБАВЛЕНИЕ НОВОГО КЛАСТЕРА
================================================================================

Автоматический способ (рекомендуется):

  Шаг 1 — раскатать экспортёры на PG-ноды:
  sudo deploy_pg.sh <os_user> <os_pass> <pg_pass> <ip1,ip2,ip3>

  Шаг 2 — раскатать экспортёры на etcd-ноды:
  sudo deploy_etcd.sh <os_user> <os_pass> <ip1,ip2,ip3>

  Шаг 3 — добавить кластер в target-файлы:
  sudo add_cluster.sh <имя> <pg_ips> <etcd_ips> <vip>

  Примеры:
  sudo deploy_pg.sh user 'Pass123' 'PgPass' 10.20.1.10,10.20.1.11,10.20.1.12
  sudo deploy_etcd.sh user 'Pass123' 10.20.1.20,10.20.1.21,10.20.1.22
  sudo add_cluster.sh orders 10.20.1.10,10.20.1.11,10.20.1.12 10.20.1.20,10.20.1.21,10.20.1.22 10.20.1.100

  Standalone PG без etcd/VIP:
  sudo deploy_pg.sh user 'Pass123' 'PgPass' 172.17.60.115
  sudo add_cluster.sh jiradb 172.17.60.115 "" ""

Ручной способ — см. ЧАСТЬ 8 (установка экспортёров вручную)
и ШАГ 4 из ЧАСТИ 5 (добавление в target-файлы вручную).

9. ПОДАВЛЕНИЕ АЛЕРТОВ (SILENCE)
================================================================================

Через UI Alertmanager:
  http://172.17.58.176:9093/#/silences/new

  Рядом с каждым активным алертом есть иконка — клик по ней
  создаёт silence с уже заполненными матчерами.

Через командную строку:
  sudo amtool silence add --comment="причина" --duration=7d \
    alertname=ReplicationLagSeconds instance=172.17.58.80:9187

Матчеры:
  instance = 172.17.58.79:9100               — конкретный сервер+порт
  instance =~ 172.17.58.79:.*                 — все порты одного сервера
  alertname = DiskSpaceWarning                — конкретный алерт
  alertname = X cluster = Y                   — алерт в конкретном кластере

Удалить silence раньше срока:
  sudo amtool silence expire ID

http://172.17.58.176:9090/targets — статус всех targets

Если DOWN — смотри Error:

  "connection refused"
    → Экспортёр слушает 127.0.0.1 а не 0.0.0.0
    → ss -tlnp | grep ПОРТ на целевом сервере
    → Поправь --web.listen-address=0.0.0.0:ПОРТ

  "context deadline exceeded" (timeout)
    → Firewall блокирует
    → Ubuntu: ufw allow from 172.17.58.176 to any port ПОРТ proto tcp
    → Oracle Linux: firewall-cmd --permanent --add-rich-rule=...

  "no route to host"
    → Сервер недоступен, ping

Полезные команды:
  sudo systemctl status prometheus alertmanager alert-webhook
  sudo journalctl -u postgres_exporter -n 50 --no-pager

  sudo /usr/local/bin/promtool check rules /etc/prometheus/rules/*.yml

11. ГРАБЛИ НА КОТОРЫЕ МЫ НАСТУПИЛИ
================================================================================

1. postgres_exporter слушает 127.0.0.1
   Решение: --web.listen-address=0.0.0.0:9187

2. Patroni /health возвращает 503 на репликах
   Решение: /liveness вместо /health

3. Patroni REST API отвечает HTTP/1.0
   Решение: valid_http_versions: ["HTTP/1.0","HTTP/1.1","HTTP/2.0"]

4. Лаг репликации огромный когда база простаивает
   Решение: queries.yml — лаг=0 если receive_lsn == replay_lsn

5. postgres_exporter ловит сам себя как "долгую транзакцию"
   Решение: AND usename != 'monitoring' в queries.yml

6. YAML отступы — только пробелы (не табы), :set paste в vi

7. etcd порт 2379 закрыт firewall

8. Имена кластеров регистрозависимые

9. Порт 9094 занят Alertmanager HA — webhook на 9095

10. Дублирование datasources в Grafana → 172 правила вместо 43

11. Спецсимволы в пароле PG ломают URL — нужен URL-encoding

12. Grafana fillOpacity > 0 рисует призрачные серии
    Решение: fillOpacity=0 на всех timeseries панелях

13. scp "Text file busy" при копировании запущенного бинарника
    Решение: systemctl stop перед cp

14. scp без -O не работает на старых серверах
    Решение: scp -O

15. sshpass -p ломает пароли со спецсимволами
    Решение: sshpass -e (через переменную SSHPASS)

16. Patroni 2.1.4 не отдаёт метрику patroni_primary и name
    Решение: recording rule patroni_primary_compat

17. pg_stat_bgwriter ошибка на PG 17+
    Решение: --no-collector.stat_bgwriter

18. SwapUsage показывает 2147479552%
    Решение: правильная формула с (SwapTotal > 104857600)

19. TooManyConnections не работает из-за разных лейблов
    Решение: ignoring(server) в выражении (или обновить queries.yml)

13. АВТОМАТИЗАЦИЯ: СКРИПТЫ РАСКАТКИ
================================================================================

Все скрипты лежат в /usr/local/bin/ на сервере мониторинга.

13.1 — deploy_pg.sh
  Раскатывает node_exporter + postgres_exporter + process_exporter
  на несколько PG-серверов за один запуск.
  Поддерживает Ubuntu (ufw) и Oracle Linux (firewalld).
  Firewall открывается ТОЛЬКО для IP мониторинга.

  Использование:
  sudo deploy_pg.sh <os_user> <os_pass> <pg_pass> <ip1,ip2,ip3>

13.2 — deploy_etcd.sh
  Раскатывает node_exporter + process_exporter на etcd-серверы.

  Использование:
  sudo deploy_etcd.sh <os_user> <os_pass> <ip1,ip2,ip3>

13.3 — add_cluster.sh
  Добавляет кластер во все 8 target-файлов одной командой.

  Использование:
  sudo add_cluster.sh <имя> <pg_ips> <etcd_ips> <vip>

  Примеры:
  sudo add_cluster.sh orders 10.1.1.1,10.1.1.2,10.1.1.3 10.2.1.1,10.2.1.2,10.2.1.3 10.1.1.100
  sudo add_cluster.sh jiradb 172.17.60.115 "" ""

  Аргументы всегда 4, разделены пробелами:
    1-имя  2-PG(через запятую)  3-etcd(через запятую или "")  4-VIP(или "")

13.4 — install_pg_exporters.sh
  Идемпотентный скрипт — можно запускать повторно.
  Останавливает сервисы перед копированием (нет "Text file busy").
  Автоматически применяет queries.yml если он в /tmp/.
  URL-кодирует спецсимволы в пароле PG.

13.5 — install_etcd_exporters.sh
  Упрощённая версия для etcd (без postgres_exporter).

13.6 — check_autoupgrade.sh
  Проверяет автообновления на серверах (Ubuntu + Oracle Linux).

  sudo check_autoupgrade.sh <os_user> <os_pass> <ip1,ip2,...>

13.7 — update_queries.sh
  Обновляет queries.yml на всех PG-серверах.

  sudo update_queries.sh <os_user> <os_pass> <ip1,ip2,...>

================================================================================
16. RECORDING RULES (СОВМЕСТИМОСТЬ PATRONI)
================================================================================

Файл: /etc/prometheus/rules/patroni_compat.yml

groups:
  - name: patroni_compat
    interval: 30s
    rules:
      - record: patroni_primary_compat
        expr: patroni_primary or patroni_master

Зачем: Patroni 2.1.x отдаёт patroni_master, а 3.x — patroni_primary.
Recording rule создаёт единую метрику patroni_primary_compat
которая работает на всех версиях.

Дашборд использует patroni_primary_compat в панели "Роли нод кластера".

Firewall на целевых серверах:

  - Сменить пароль admin
  - Отключить телеметрию (check_for_updates = false)

Исходящий трафик с сервера мониторинга:

  - grafana.com:443 — НЕ НУЖЕН (отключить)

18. ORACLE LINUX (ОТЛИЧИЯ ОТ UBUNTU)
================================================================================

Бинарники экспортёров — те же самые (linux-amd64), работают на любом дистрибутиве.

Отличия:

  Firewall:
    Ubuntu: ufw allow from 172.17.58.176 to any port 9100 proto tcp
    OL:     firewall-cmd --permanent --add-rich-rule="rule family=ipv4
            source address=172.17.58.176 port port=9100 protocol=tcp accept"
            firewall-cmd --reload

  SELinux (если Enforcing):
    getenforce
    Если Enforcing и экспортёры не стартуют:
      setsebool -P nis_enabled 1
    Или временно: setenforce 0

  Нет sudo у user:
    Использовать su - (root) для установки

  PostgreSQL 17+ на Oracle Linux:
    Добавить --no-collector.stat_bgwriter в systemd unit postgres_exporter
    (ошибка "column checkpoints_timed does not exist")

19. МАССОВЫЕ ОПЕРАЦИИ
================================================================================

19.1 — Обновление queries.yml на всех PG-серверах

  Шаг 1: обновить эталон
    sudo vi /opt/exporters-offline/queries.yml

  Шаг 2: раскатать
    export SSHPASS='ПАРОЛЬ'
    for ip in IP1 IP2 IP3; do
      echo "=== $ip ==="
      sshpass -e scp -O -o StrictHostKeyChecking=no \
        /opt/exporters-offline/queries.yml user@$ip:/tmp/
      sshpass -e ssh -o StrictHostKeyChecking=no user@$ip \
        "echo '$SSHPASS' | sudo -S bash -c 'cp /tmp/queries.yml \
        /etc/postgres_exporter/queries.yml && \
        chown postgres_exporter:postgres_exporter /etc/postgres_exporter/queries.yml && \
        systemctl restart postgres_exporter && rm /tmp/queries.yml && echo OK'"
    done

  Или через update_queries.sh:
    sudo update_queries.sh user 'ПАРОЛЬ' ip1,ip2,ip3,...

19.2 — Проверка серверов без queries.yml

  curl -s --data-urlencode 'query=pg_up unless on(instance) (pg_stat_activity_summary_count * 0 + 1)' \
    http://localhost:9090/api/v1/query | python3 -m json.tool | grep -E '"instance"|"cluster"'

19.3 — Проверка автообновлений

  sudo check_autoupgrade.sh user 'ПАРОЛЬ' ip1,ip2,...

19.4 — Отключение автообновлений (Ubuntu)

  cat > /tmp/20auto-upgrades << 'EOF'
  APT::Periodic::Update-Package-Lists "0";
  APT::Periodic::Unattended-Upgrade "0";
  EOF

  export SSHPASS='ПАРОЛЬ'
  for ip in IP1 IP2; do
    echo "=== $ip ==="
    sshpass -e scp -O -o StrictHostKeyChecking=no /tmp/20auto-upgrades user@$ip:/tmp/
    sshpass -e ssh -o StrictHostKeyChecking=no user@$ip \
      "echo 'ПАРОЛЬ' | sudo -S bash -c 'cp /tmp/20auto-upgrades \
      /etc/apt/apt.conf.d/20auto-upgrades && systemctl disable --now \
      unattended-upgrades apt-daily.timer apt-daily-upgrade.timer 2>/dev/null; \
      cat /etc/apt/apt.conf.d/20auto-upgrades; rm -f /tmp/20auto-upgrades'"
  done
